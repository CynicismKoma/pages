## 目录

## 创建博客文章

要撰写新博客文章，在 `src/content/posts/` 目录下创建一个 markdown（或 MDX）文件。

你可以将文章组织到子目录中，以便更轻松地管理内容。子目录名称会成为文章 URL 的一部分。例如，`src/content/posts/2025/example-post.md` 将通过 `/posts/2025/example-post` 访问。

如果只想用子目录进行组织而不影响 URL，请在文件夹名称前加上下划线（`_`）。

```bash
# 示例：文章文件路径及其 URL
src/content/posts/very-first-post.md          -> mysite.com/posts/very-first-post
src/content/posts/2025/example-post.md        -> mysite.com/posts/2025/example-post
src/content/posts/_2026/another-post.md       -> mysite.com/posts/another-post
src/content/posts/docs/_legacy/how-to.md      -> mysite.com/posts/docs/how-to
src/content/posts/Example Dir/Dummy Post.md   -> mysite.com/posts/example-dir/dummy-post
```

> [!TIP]
> 以 `_` 前缀命名的文件和目录会被排除在路由之外。可将它们用于草稿、共享资源或仅限内部使用的内容。

## Frontmatter

Frontmatter 是存储博客文章元数据的主要位置。它位于文件顶部，采用 YAML 格式。在 [Astro 文档](https://docs.astro.build/en/guides/markdown-content/) 中了解更多关于 frontmatter 及其用法的信息。

以下是每篇文章的 frontmatter 属性列表：

<ResponsiveTable variant="striped-minimal">

| 属性               | 描述                                                                                         | 备注                                         |
| ------------------ | -------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| **_title_**        | 文章标题 (h1)                                                                                | 必填<sup>\*</sup>                          |
| **_description_**  | 文章描述。用于文章摘要和网站描述。                                                            | 必填<sup>\*</sup>                          |
| **_pubDatetime_**  | ISO 8601 格式的发布时间。                                                                     | 必填<sup>\*</sup>                          |
| **_modDatetime_**  | ISO 8601 格式的修改时间。（仅在文章修改时添加此属性）                                          | 可选                                       |
| **_author_**       | 文章作者。                                                                                   | 默认 = `site.author`                        |
| **_featured_**     | 是否在首页的精选区域显示此文章。                                                              | 默认 = false                                |
| **_draft_**        | 将此文章标记为"未发布"。                                                                      | 默认 = false                                |
| **_tags_**         | 文章的相关关键词。以 YAML 数组格式编写。                                                       | 默认 = others                               |
| **_ogImage_**      | 文章的 OG 图片。用于社交媒体分享和 SEO。可以是远程 URL 或相对于当前文件夹的图片路径。           | 默认 = `site.ogImage` 或生成的 OG 图片 |
| **_canonicalURL_** | 规范 URL（绝对路径），当文章已存在于其他来源时使用。                                            | 默认 = `Astro.site` + `Astro.url.pathname`  |
| **_hideEditPost_** | 隐藏文章标题下方的编辑文章按钮。仅对当前文章生效。                                               | 默认 = false                                |
| **_timezone_**     | 为当前文章指定 IANA 格式的时区。仅针对此文章覆盖全局 `site.timezone` 配置。                     | 默认 = `site.timezone`                      |

</ResponsiveTable>

> [!TIP]
> 你可以在控制台中运行 `new Date().toISOString()` 来获取 ISO 8601 日期时间。

frontmatter 中只需指定 `title`、`description` 和 `pubDatetime` 字段。

标题和描述（摘要）对搜索引擎优化（SEO）很重要，因此 AstroPaper 鼓励你在所有博客文章中都包含它们。

如果你在博客文章中省略了 `tags`（即未指定标签），则该文章将使用默认标签 `others`。你可以在 `src/content.config.ts` 中设置默认标签：

```ts file="src/content.config.ts"
// ...
tags: z.array(z.string()).default(["others"]), // 将 "others" 替换为你想要的任何内容
// ...
```

### 示例 Frontmatter

以下是一篇文章的 frontmatter 示例。

```yaml file="src/content/posts/sample-post.md"
---
title: 文章标题
author: 你的名字
pubDatetime: 2022-09-21T05:17:19Z
featured: true
draft: false
tags:
  - some
  - example
  - tags
ogImage: ../../assets/images/example.png # src/assets/images/example.png
# ogImage: "https://example.org/remote-image.png" # 远程 URL
description: 这是示例文章的示例描述。
canonicalURL: https://example.org/my-article-was-already-posted-here
---
```

### VS Code 代码片段（可选）

AstroPaper 包含工作区代码片段，可加快创建新文章的速度：

- **frontmatter**：插入推荐的 frontmatter 块
- **template**：插入基本文章模板（包括 `## 目录`）

这些代码片段位于 `.vscode/astro-paper.code-snippets`。如果你使用 VS Code（或 Cursor），打开工作区时它们应自动可用。

## Callouts（标注）

AstroPaper 从 v6.1 开始支持 callouts。它们使用由 `rehype-callouts`（Obsidian 主题）驱动的简单块引用语法。

以下是最常用的类型：

> [!NOTE]
> 读者应注意的补充信息。

> [!TIP]
> 有用的建议、快捷方式或最佳实践。

> [!WARNING]
> 可能出错或产生意外后果的事项。

> [!DANGER]
> 存在失败、数据丢失或错误行为的严重风险。

> [!INFO]
> 中立的上下文信息——比 note 的紧急程度低。

> [!SUCCESS]
> 确认某操作成功或正确。

支持类型的完整列表包括：`NOTE`、`ABSTRACT`、`INFO`、`TODO`、`TIP`、`SUCCESS`、`QUESTION`、`WARNING`、`FAILURE`、`DANGER`、`BUG`、`EXAMPLE`、`QUOTE`——每种都有其自己的图标和颜色。许多类型也接受别名（例如 `TIP` 的 `HINT` 和 `IMPORTANT`，`WARNING` 的 `CAUTION`）。请参阅 [rehype-callouts 文档](https://github.com/lin-stephanie/rehype-callouts) 获取完整参考。

### 可折叠的 Callouts

在类型后添加 `-` 使 callout 默认折叠，添加 `+` 使其展开但可折叠：

> [!WARNING]- 阅读前请先查看
> 此内容在读者展开之前是隐藏的。适用于较长且会中断阅读流程的说明。

> [!TIP]+ 高级提示（默认展开）
> 此内容默认展开但可折叠。非常适合你希望首次加载时可见的可选详细信息。

### 自定义标题

通过在类型后添加文本，将默认类型标签替换为你喜欢的任意标题：

> [!NOTE] 你知道吗？
> 类型后的文本将成为 callout 的标题。如果省略，将自动使用类型名称。

### 语法总结

```md
> [!NOTE]
> 补充信息。

> [!WARNING]- 默认折叠
> 展开前隐藏。

> [!TIP]+ 展开但可折叠
> 默认展开。

> [!DANGER] 自定义标题
> 替换默认标题。
```

## 添加目录

默认情况下，文章不包含任何目录（TOC）。要添加目录，请以 h2 标题（Markdown 中的 `##`）编写 `目录` 并将其放在你希望显示的位置：

```md
---
# frontmatter
---

以下是在 AstroPaper 博客主题中创建新文章的一些建议、技巧和窍门。

<!-- [!code ++] -->
## 目录

<!-- 文章的其余部分 -->
```

## 标题

关于标题有一点需要注意。AstroPaper 博客文章使用 frontmatter 中的 `title` 作为文章的主标题。因此，文章中的其余标题应使用 `h2` ~ `h6`。

此规则非强制性，但强烈建议用于视觉、可访问性和 SEO 目的。

## 语法高亮

AstroPaper 使用 [Shiki](https://shiki.style/) 作为默认语法高亮器，并使用 [@shikijs/transformers](https://shiki.style/packages/transformers) 增强围栏代码块。如果你不想使用 transformers，可以移除它们：

```bash
pnpm remove @shikijs/transformers
```

```ts file="astro.config.ts"
// ...
// [!code --:5]
import {
  transformerNotationDiff,
  transformerNotationHighlight,
  transformerNotationWordHighlight,
} from "@shikijs/transformers";

export default defineConfig({
  // ...
  markdown: {
    remarkPlugins: [remarkToc, [remarkCollapse, { test: "Table of contents" }]],
    shikiConfig: {
      themes: { light: "min-light", dark: "night-owl" },
      defaultColor: false,
      wrap: false,
      transformers: [
        transformerFileName(),
        // [!code --:3]
        transformerNotationHighlight(),
        transformerNotationWordHighlight(),
        transformerNotationDiff({ matchAlgorithm: "v3" }),
      ],
    },
  },
  // ...
});
```

## 存储博客内容图片

以下是存储图片并在 markdown 文件中使用它们的两种方法。

> [!IMPORTANT]
> 如果你需要在 markdown 中设置优化图片的样式，应[使用 MDX](https://docs.astro.build/en/guides/images/#images-in-mdx-files)。

### 在 `src/assets/` 目录中（推荐）

你可以将图片存储在 `src/assets/` 目录中。这些图片将通过 Astro 的 [Image Service API](https://docs.astro.build/en/reference/image-service-reference/) 自动优化。

你可以使用相对路径或别名路径（`@/assets/`）来引用这些图片。

示例：假设你想显示 `example.jpg`，其路径为 `src/assets/images/example.jpg`。

```md
![示例](@/assets/images/example.jpg)

<!-- 或 -->

![示例](../../assets/images/example.jpg)

<!-- 在 markdown 中使用 img 标签或 Image 组件无效 ❌ -->
<img src="@/assets/images/example.jpg" alt="示例">
<!-- ^^ 这是错误的 -->
```

> [!TIP]
> 从技术上讲，你可以将图片存储在 `src` 下的任何目录中。`src/assets` 只是一个建议。

### 在 `public/` 目录中

你可以将图片存储在 `public/` 目录中。请注意，存储在 `public/` 中的图片不会被 Astro 处理，这意味着它们未经优化，你需要自行处理图片优化。

对于这些图片，请使用绝对路径。它们可以使用 [markdown 图片语法](https://www.markdownguide.org/basic-syntax/#images-1) 或 HTML `img` 标签显示。

示例：假设 `example.jpg` 位于 `public/assets/images/example.jpg`。

```md
![示例](/assets/images/example.jpg)

<!-- 或 -->

<img src="/assets/images/example.jpg" alt="示例">
```

## 额外提示

### 图片压缩

> [!WARNING]
> 将图片放入博客文章时（尤其是 `public/` 目录中的图片），请先进行压缩。未经优化的图片会严重损害页面性能。

推荐的图片压缩网站：

- [TinyPng](https://tinypng.com/)
- [TinyJPG](https://tinyjpg.com/)

### OG 图片

如果文章未指定 OG 图片，将使用默认 OG 图片。虽然不是必需的，但建议在 frontmatter 中指定与文章相关的 OG 图片。推荐 OG 图片尺寸为 **_1200 X 640_** px。

> [!TIP]
> 自 AstroPaper v1.4.0 起，如果未指定 OG 图片，将自动生成。查看[公告](https://astro-paper.pages.dev/posts/dynamic-og-image-generation-in-astropaper-blog-posts/)。
